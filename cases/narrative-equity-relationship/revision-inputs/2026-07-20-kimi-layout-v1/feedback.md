# 股权关系叙事可视化：首轮视觉修订反馈

## 本轮目标

在不重写现有组件、不改变数据协议、章节播放能力和公开 API 的前提下，参照 `reference-01.png`，将当前实现收敛为一个可用于“股权演变叙事”的总览视图。重点是让用户先看懂主控关系与关键持股链路，再阅读细节。

## F-01：建立清晰的主叙事层级

当前首屏应优先呈现从核心人物/家族、控制主体、上市公司到品牌/下属实体的主链路；非主链路（例如监管、政府、投资局等）作为旁支呈现，不能抢占主视觉中心。

期望：

- 主链路形成稳定的自上而下层级，核心节点位于视觉中心。
- 旁支关系放在主链路两侧，以较低视觉权重表达，避免破坏主链路阅读顺序。
- 进入章节和返回总览时，已确定的核心节点位置应尽量保持稳定。

验收：默认首屏在 3 秒内能识别“核心人物/家族 → 控制主体 → 上市公司 → 品牌”的关系方向。

## F-02：节点视觉语义要区分人物、组织与品牌

参考图中，人物、组织/公司、品牌使用不同图标；节点名称采用胶囊标签，关键实体使用蓝色强调，普通人物和旁支实体以深色或低权重样式呈现。

期望：

- 人物、组织/公司、品牌在图标、颜色或外形上具备稳定且可辨认的区分。
- 核心控制主体、上市公司和最终品牌使用强调色；强调不等于所有节点都变蓝。
- 图标、名称胶囊、状态角标共同作为节点外包围盒参与布局，不能互相遮挡。

验收：节点类型不依赖阅读长文本即可辨认；长名称不与相邻节点、边或标签重叠。

## F-03：关系线、箭头与标签保持可读

参考图中关系线使用浅色细线，箭头表达方向；关系标签放在线旁，必要时换行并使用白色背景保证可读。实线、虚线、持股比例和关系文字分别表达不同语义。

期望：

- 连线端点落在节点外包围盒边界，不能穿过图标或名称胶囊。
- 主链路方向和持股比例优先可读；标签可换行，但关键百分比不得被截断。
- 虚线用于补充/弱关系时应与实线有明确区分；不因视觉修订而删除原有关系语义。

验收：默认视图、缩放、容器 Resize 和章节切换后，主关系标签仍可读，且没有明显的线穿节点、标签压线或标签互相覆盖。

## F-04：保持演示/叙事播放体验

底部章节导航和播放控制是叙事体验的一部分，应保持现有功能。视觉修订不能导致章节跳转、播放/暂停、前后步骤切换或总览返回失效。

期望：

- 当前章节相关的节点和边可被强调；非焦点元素降低权重但不无故消失。
- 切换步骤、暂停恢复和 Resize 后不能出现明显跳动、闪烁或旧状态残留。

## 参考图使用规则

- `reference-01.png` 重点参考：总体层级、节点类型语义、胶囊标签、主辅关系权重、连线标签和底部章节导航的视觉组织。
- 不要求像素级复刻，也不得复制截图中的真实业务实体、文字、数据或图标素材；继续使用现有脱敏数据和资源。
- 图片未明确表达的业务规则不得臆造；存在冲突时以既有 requirement ledger 和数据协议为准，并记录在 `docs/revision/visual-grounding.md`。

## 不可破坏约束

- 不修改既有 `build`、`typecheck`、`test` 脚本。
- 不删除既有数据协议、组件 API、章节/步骤播放、事件和生命周期能力。
- 不硬编码截图中的绝对坐标、实体名称或持股数据。
- 本轮只做视觉表达、布局和相关交互稳定性修订，不做无关的大范围架构重写。
